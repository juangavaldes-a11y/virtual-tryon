# Virtual Fitting Room

Web app where shoppers put a clothing company's garments on virtual models. Two modes:

- **Instant preview** - layer garment images on a model and drag, resize, rotate, flip, fade and reorder them.
- **Realistic preview** - a self-hosted AI try-on model ([Leffa](https://github.com/franciszzj/Leffa), MIT) renders the garment onto a photo of the model.

Shoppers can also save looks, reload them and download a PNG. Staff add garments to the catalog by uploading product photos (optional white-background removal).

## Architecture

```
frontend/         Vite + React 19 + MUI 9 + react-konva editor        :5173
backend/          Sails.js 1.5 API + PostgreSQL (CRUD, uploads, gateway) :1337
tryon-service/    FastAPI wrapper around Leffa (needs an NVIDIA GPU)     :8000
docker-compose.yml  PostgreSQL 17
```

The browser only talks to Sails. Sails forwards `POST /api/tryon` to the GPU service, so the GPU port never needs to be public.

## Quick start

```bash
docker compose up -d                        # PostgreSQL (user/password/db: tryon)
cd backend  && npm install && npm run dev   # API on :1337, auto-migrates and seeds 3 models
cd frontend && npm install && npm run dev   # app on :5173 (proxies /api and /uploads)
```

Realistic preview is optional; see [tryon-service/README.md](tryon-service/README.md) to run the GPU service.

## Configuration

| Variable | Where | Default |
|---|---|---|
| `DATABASE_URL` | backend | `postgresql://tryon:tryon@localhost:5432/tryon` |
| `CORS_ORIGINS` | backend | `http://localhost:5173` (comma separated) |
| `PORT` | backend (production) | `1337` |
| `TRYON_URL` | backend | `http://localhost:8000` |
| `VITE_API_TARGET` | frontend dev proxy | `http://localhost:1337` |
| `LEFFA_DIR`, `TRYON_STEPS`, `TRYON_GUIDANCE` | tryon-service | `./Leffa`, `30`, `2.5` |

## API

REST CRUD is generated by Sails blueprints under `/api`: `mannequin`, `garment`, `design`
(for example `GET /api/garment`, `POST /api/design`).

| Route | Purpose |
|---|---|
| `POST /api/upload/image` | Multipart field `image` (PNG/JPEG/WebP, 8 MB max, type checked from file bytes). Returns `{ url }`. |
| `POST /api/tryon` | Multipart: `category` (`upper_body`, `lower_body`, `dresses`) **first**, then `person` and `garment`. Returns a PNG, or 503 if the GPU service is down. |
| `GET /api/health` | Liveness check. |

## Models and garments

- The three seeded models (Sofia, Emma, Mei) are **illustrations** in `frontend/public/models`. They are stand-ins: the AI try-on needs real front-facing, full-body photos on a plain background. Replace the images and update `backend/config/bootstrap.js`.
- Garments should be front-facing flat-lay or ghost-mannequin photos, cropped tight. Realistic preview supports tops, outerwear, bottoms and dresses (not accessories).

## Before going to production

- **No authentication yet.** Anyone can add garments, delete looks or call `/api/tryon` (which uses your GPU). Add login, admin-only catalog routes and rate limiting.
- Check the license and training-data terms of the try-on model for commercial use. Most open try-on models (CatVTON, IDM-VTON, FitDiT) are non-commercial.
- Move uploads from `backend/uploads` to object storage (S3 or similar).
- Production runs with `migrate: 'safe'`, so manage schema with real migrations. Set a real `dataEncryptionKeys.default` in `backend/config/models.js`.
